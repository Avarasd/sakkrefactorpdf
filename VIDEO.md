# Cinematic Carousel Walkthrough Video

A short cinematic walkthrough that slides through the four carousel pages and
zooms into the C / C++ code windows, popping up each slide's callout. It is
rendered from the existing deck markup and encoded to `carousel_walkthrough.mp4`
(1080x1350, H.264).

This pipeline is **additive**. It does not modify `index.html`, `style.css`, or
`app.js`. It reuses `style.css` so the video matches the deck exactly.

## Files

- `cinematic.html` — standalone stage that reuses the four slide sections and
  links `style.css`. Hidden toolbar (not copied), no `app.js`.
- `cinematic.css` — cinematic-only layout (the fixed 1080x1350 `#stage`, the
  `#camera` layer, slide positioning, chrome overrides). Never touches the deck.
- `cinematic.js` — the deterministic animation engine. One global
  `window.seek(t)` sets the exact visual state for time `t` with no dependence
  on wall-clock time or `requestAnimationFrame`. Exposes `window.seek`,
  `window.TOTAL_DURATION`, and `window.READY` (set true only after
  `document.fonts.ready` resolves and layout is measured).
- `make_video.js` — captures one PNG per frame via headless Chrome, then encodes
  with ffmpeg.

## Prerequisites

- **Node** (tested with v26) and `npm`.
- **puppeteer** — `npm install puppeteer` (already installed here). Used to drive
  one headless Chrome for the whole run.
- **ffmpeg** with `libx264` (tested with ffmpeg 9 at `/opt/homebrew/bin/ffmpeg`).
- **Google Chrome** at `/Applications/Google Chrome.app/...`. The pipeline
  launches this trusted system Chrome via puppeteer's `executablePath`, because
  puppeteer's freshly downloaded Chrome-for-Testing can stall on macOS
  first-launch security verification.

## Regenerate the video

From the workspace root:

```sh
node make_video.js
```

It opens `cinematic.html` headless, waits for `window.READY`, captures
`round(fps * TOTAL_DURATION) + 1` frames at 30 fps into `.video_frames/`, then
runs:

```sh
ffmpeg -y -framerate 30 -i .video_frames/frame-%05d.png \
  -c:v libx264 -pix_fmt yuv420p -crf 18 -preset slow carousel_walkthrough.mp4
```

Output: `carousel_walkthrough.mp4` in the workspace root. On a successful encode
`.video_frames/` is deleted; on failure it is left in place for debugging.

### Fallback capture

If puppeteer cannot launch headless after a genuine attempt, `make_video.js`
falls back to the Chrome CLI `--screenshot` path: one `Google Chrome --headless`
invocation per frame against `cinematic.html?t=<seconds>` (the page calls
`seek(t)` on load when a `?t=` query is present). This needs no page changes.

## Tweak the timing / framing

All timing lives in **one place**: the `SEGMENTS`/`CALLOUT_POPS` timeline built by
`buildTimeline()` in `cinematic.js`. Each camera move is a `{start, end, from, to}`
tween of the camera transform (eased with `easeInOutCubic`); `TOTAL_DURATION` is
derived from the last segment's end. Per-case-slide beats (settle, zoom to C,
hold, pan to C++, hold + callout pop, zoom out) are generated by the `caseSlide()`
helper. Zoom framing is computed from each `.code-window`'s live layout rect
(`frameRect` + `rectInCamera`), so it stays correct regardless of layout.

Capture settings (`FPS`, resolution, paths) are constants at the top of
`make_video.js`.
